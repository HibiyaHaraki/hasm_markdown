# HASM Markdown Desktop App - UI/UX Design & Architecture Requirements

## 1. Design Concept & Brand Identity
- **Logo Harmony & Aesthetic Alignment:**
  - The UI design must harmonize seamlessly with the HASM brand identity and calculated geometric logos (`hasm_logo` and `hasm_markdown_logo`).
  - Subtle geometric precision, refined borders, and mathematical gradient accents derived from the logo's aesthetic should be reflected in UI dividers, active states, and focal points without cluttering the workspace.
- **Tone & Atmosphere:** Avoid flashy animations, bright primary colors, or overly modern flat-UI tropes. Embrace generous white space, delicate margins, and a quiet, high-end, contemplative reading/writing experience.
- **Typography:**
  - The primary typeface for the editor, Markdown preview, and body text must be an elegant Japanese Serif (Mincho) font family (e.g., `Yu Mincho`, `游明朝`, `Georgia`, or generic `serif`).
  - For Serif elements, apply slightly wider letter spacing (`letter-spacing: 0.03em+`) and comfortable line heights (`line-height: 1.7 - 1.8`) for optimal readability and a traditional literary print aesthetic.
  - UI control labels (buttons, toolbars) may use a clean, subtle font structure, but must maintain strict visual hierarchy and quiet elegance alongside the Serif body text.
- **Persistence:** Save this design policy to `docs/design-policy.md` and explicitly include these rules in `.github/copilot-instructions.md`.

## 2. Dynamic Color Pattern & Theme System
- Enable users to dynamically select and switch color patterns provided by the `hasm_color_pattern` submodule via the menu.
- Theme switching **MUST** be implemented using **CSS Custom Properties (CSS Variables)** defined at the `:root` level.
- All UI elements, the text editor, and the rendered HTML preview generated by `markdown-it` must instantaneously adapt and synchronize with the active CSS variables.
- Base background tones should avoid pure `#000000` or `#FFFFFF`. Instead, use deep, muted darks (e.g., `#0D1117`) or subtle paper-like off-whites (e.g., `#FBFBFB` / `#F4F3EF`) to match the logo variants.

## 3. UI/UX, Layout & Responsive Design
- **CSS Library Restrictions:** 
  - **Bootstrap** is permitted **ONLY** for grid layout, flexbox utilities, and structural positioning (`d-flex`, `col-*`, etc.).
  - Default Bootstrap component styles (buttons, cards, borders, rounded corners) **MUST BE OVERRIDDEN** with custom CSS to match the quiet, custom HASM aesthetic. No other third-party UI libraries are allowed.
- **Navigation & Responsiveness:**
  - The main navigation/settings menu must be a minimal hamburger menu that only displays when clicked (off-canvas / drawer / overlay mode).
  - The entire layout must be responsive and adapt fluidly to various desktop window dimensions.
- **Font Size Scaling:**
  - Provide a text size switcher supporting "Small", "Medium", and "Large" scale presets by dynamically updating a root CSS variable (e.g., `--base-font-size`).

## 4. Editor & Preview Pane
- Provide a dual-pane layout (Editor on the left, `markdown-it` preview on the right) as the default view.
- Ensure smooth scrolling, clean border division matching the logo’s crisp line geometry, and optional focus modes (Editor-only / Preview-only).
